# 03. Система сохранения внешности Фомы

## 1. Почему это главная техническая проблема

Видеомодели не «помнят» персонажа. Каждый кадр они рисуют заново, опираясь на то, что им дали. Поэтому без системы Фома будет каждый раз немного другим: маска чуть шире, трещина в другом месте, худи станет курткой. Зритель этого может не сформулировать, но почувствует «дешёвый AI-контент».

### Хорошая новость: маска — наше преимущество
- Лицо — самая капризная часть для ИИ (мимика, возраст, «плывущая» идентичность). У Фомы его нет.
- Маска — это по сути **логотип на голове**: плоская графика, которую можно жёстко зафиксировать.
- Глаза-светлячки — простая форма, легко проверяется и легко **дорисовывается/корректируется в посте** (свечение можно добавить композитингом поверх любого кадра).
- Говорить без губ → **липсинк не нужен**.

### Плохая новость: асимметрия
Асимметричная маска — главный риск. Модели обожают зеркалить: при повороте героя или при генерации «вида сзади-сбоку» чёрная половина может «переехать» на другую сторону. Поэтому:
- асимметрия описывается **относительно самого Фомы** («на правой половине его лица, у зрителя слева при виде анфас»);
- в монтаже **запрещено** отражать кадры по горизонтали (классический монтажный приём «flip, чтобы исправить направление взгляда» нам недоступен);
- в QC отдельный пункт: «сторона чёрного / белого верная?».

## 2. Пять уровней защиты

| Уровень | Что | Когда внедряем |
|---|---|---|
| **1. Текстовый замок** | `bible/foma.yaml` — неизменяемый блок описания, который вставляется в **каждый** промпт дословно. Описание всегда одними и теми же словами, в одном порядке | сейчас ✅ |
| **2. Эталонные изображения** | Master-кадр (анфас, полный рост, нейтральный свет) + turnaround (перед, 3/4, профиль, спина) + лист маски крупно + 6–10 поз + свет: «лунный холодный», «фонарик», «полутьма». Всегда передаются в модель как референсы | после получения утверждённого дизайна |
| **3. Только image-to-video** | Видео **никогда** не генерируется из одного текста для кадров с Фомой. Сначала утверждённый ключевой кадр, потом его оживление. Для сложных кадров — начальный **и** конечный кадр | с первого теста |
| **4. LoRA Фомы** | Дообучение генератора картинок (Flux / Qwen-Image) и, при переходе на Wan, видео-LoRA на 20–40 утверждённых изображениях. Даёт стабильность «из коробки» | после теста T-01, когда наберём датасет |
| **5. 3D-манекен** | Простая 3D-модель Фомы (Hunyuan3D-2 из turnaround → доводка в Blender, или фрилансер). Рендерим из неё позу/ракурс как основу ключевого кадра → геометрия маски и пропорции не могут «уплыть» | если после T-01 дрейф > допустимого |

Уровень 5 — это мост к «настоящей» 3D-анимации: при росте канала можно анимировать Фому в Blender полностью, а ИИ использовать только для стилизации и фонов.

## 4. Правила для промптов

1. Блок `lock_prompt_en` из `foma.yaml` — **дословно** в каждом промпте с Фомой.
2. Промпты для моделей пишутся **на английском** (модели обучены в основном на английских подписях), сценарий и реплики — на русском.
3. Описывай, что должно быть, а не чего быть не должно («маска полностью закрывает лицо», а не «без рта»). Исключения-запреты — коротким списком в конце.
4. В одном кадре не больше двух персонажей.
5. Не просить у модели «сыграть» сразу несколько действий. Один кадр = одно действие.
6. Длина клипа 4–8 с. Длиннее — растёт дрейф.
7. Для продолжения действия: последний **хороший** кадр предыдущего клипа → первый кадр следующего (с проверкой, не «поплыл» ли он).

## 5. QC-чеклист кадра с Фомой

Проверяется на стоп-кадрах (каждые 0.5 с + первый/последний кадр). Любой «нет» в блоке **критично** = дубль бракуется.

**Критично**
- [ ] Форма маски совпадает с master (контур, пропорции).
- [ ] Сторона чёрного/белого верная (не зеркальная).
- [ ] Трещины на своих местах, их количество не изменилось.
- [ ] Глаза: форма и размер как в эталоне, цвет свечения белый (не голубой, не жёлтый).
- [ ] Лицо полностью закрыто, нигде не проступает рот/нос/кожа.
- [ ] Одежда: чёрное оверсайз-худи, очень широкие карго, массивные тёмные кроссовки — без логотипов, надписей, лишних деталей.
- [ ] Пропорции тела и рост те же.
- [ ] Руки: 5 пальцев, нет слияний с предметами.

**Важно**
- [ ] Силуэт читается на тёмном фоне.
- [ ] Свечение глаз согласовано со светом сцены (в темноте видно, на свету не «выжжено»).
- [ ] Движение без «плавания» ног и телепортаций.
- [ ] Предметы в руках не меняются (фонарик остаётся фонариком).

**Оценка дубля:** 0 критичных ошибок + ≤ 1 важная = «зелёный». Ведём в `shotlist.csv` колонку `qc`.

## 6. Метрика стабильности (для теста T-01)

По каждому кадру теста: процент дублей, прошедших «критично» с первой попытки.
- ≥ 60% — система работает, можно планировать выпуск.
- 30–60% — внедряем LoRA (уровень 4) и повторяем тест.
- < 30% — внедряем 3D-манекен (уровень 5) или меняем модель.
