# 02. Технологическая архитектура и производственный pipeline

## 1. Главный принцип

**Фильм — это не «один большой промпт», а таблица.** Каждый кадр — строка в шот-листе с ID (`E01_S03_SH012`). У строки есть ключевой кадр, промпт движения, реплики, звук, статус и оценка QC. Всё, что генерируется, привязано к ID. Тогда:
- можно перегенерировать один кадр, не трогая фильм;
- можно сменить модель видео, не переписывая сценарий;
- можно автоматически собрать фильм из того, что уже утверждено.

Аналогия: сценарий — это рецепт, шот-лист — техкарта кухни, генераторы — повара. Повара можно заменить, техкарта остаётся.

## 3. Три класса кадров (главное средство экономии)

Не каждый кадр надо «оживлять» дорогой видеомоделью. В хорроре долгие статичные планы — часть языка.

| Класс | Что это | Как делается | Доля в выпуске | Цена |
|---|---|---|---|---|
| **A — анимация героя** | Фома двигается, действует, реагирует | Kling/Seedance image-to-video | 30–40% | дорого |
| **B — «живой» кадр** | Локация, деталь, атмосфера: туман ползёт, лампа мигает, дверь чуть приоткрыта | дешёвая модель / Wan / короткий клип + зацикливание | 30–40% | дёшево |
| **C — 2.5D/композитинг** | Статичный ключевой кадр + параллакс + туман + мерцание света + зерно, Фома неподвижно смотрит | ffmpeg/Resolve/After Effects, без генерации видео | 20–30% | почти бесплатно |

Тишина + класс C (герой замер, свет мигает, слышно только дыхание) часто страшнее любого движения.

## 4. Pipeline выпуска: кто что делает

| # | Этап | Делаю я | Нужно от тебя | Выход | Время* |
|---|---|---|---|---|---|
| 1 | Идея | 5–10 логлайнов на выбор | выбор 1 | `logline.md` | 0.5 д |
| 2 | Тритмент | структура из 9 актов ТЗ, поворот | утверждение | `treatment.md` | 0.5 д |
| 3 | Сценарий (этап A) | полный текст с диалогами | правки | `script.md` | 1–2 д |
| 4 | Раскадровка (этап B) | шот-лист: сцена, длительность, локация, действие, ракурс, камера, свет, эмоция, звук, класс A/B/C | — | `shotlist.csv` | 1 д |
| 5 | Аниматик | карточки + черновой голос + тайминг | просмотр, «ритм ок?» | `animatic.mp4` | 0.5 д |
| 6 | Визуальные материалы (этап C) | промпты локаций, ключевых кадров; генерация при наличии API | оплата/ключи, отбор лучших | `assets/` | 2–4 д |
| 7 | Анимация (этап D) | промпты движения, генерация при наличии API, QC стоп-кадров | финальный отбор дублей | `shots/` | 4–8 д |
| 8 | Озвучка (этап E) | голос второстепенных, тайминг | запись Фомы (если живой голос) | `audio/vo/` | 1 д |
| 9 | Звук (этап F) | эмбиенты, фоли, музыка, микс | — | `audio/` | 1–2 д |
| 10 | Монтаж (этап G) | автосборка, OTIO-таймлайн для Resolve, громкость | финальная полировка в Resolve | `export/` | 1–2 д |
| 11 | QC | чеклист 10 пунктов + отчёт | финальное «да» | `qc_report.md` | 0.5 д |
| 12 | Упаковка | названия, обложки, описание, теги, закреп | выбор обложки, загрузка | `youtube.md` | 0.5 д |

\* Ориентир для выпуска 15–20 минут после того, как конвейер отлажен. Первые 2–3 выпуска — в 2–3 раза дольше.

## 5. Структура папок

```
foma-studio/
├── README.md
├── docs/                         # регламенты студии
├── bible/                        # ИСТИНА о мире и герое
│   ├── foma.yaml                 # паспорт Фомы (текстовый «замок»)
│   ├── reference/                # утверждённые изображения Фомы (master, turnaround, позы)
│   ├── lora/                     # обученные LoRA + датасет (ссылки, веса — вне git)
│   └── voices.yaml               # голоса персонажей: сервис, voice_id, настройки
├── style/
│   ├── look.yaml                 # палитра, свет, камера, «запрещённые» решения
│   └── reference/                # мудборд (свои кадры, не чужие)
├── tools/                        # скрипты конвейера
├── production/
│   └── ep001_<slug>/
│       ├── 00_story/             # logline.md, treatment.md, script.md
│       ├── 01_board/             # shotlist.csv, dialogue.csv, board/*.png
│       ├── 02_assets/            # plates (локации), keyframes/<SHOT_ID>_start.png
│       ├── 03_shots/             # <SHOT_ID>_take01.mp4 …  + qc/*.jpg
│       ├── 04_audio/             # vo/, sfx/, amb/, music/
│       ├── 05_edit/              # timeline.otio, animatic.mp4
│       ├── 06_export/            # финальный мастер
│       ├── 07_youtube/           # titles.md, thumbnails/, description.md
│       └── qc_report.md
```

### Именование
`E01_S03_SH012_take02.mp4` — выпуск, сцена, кадр, дубль. Никаких «final_final2.mp4».

### Хранение
- **В git:** тексты, YAML, CSV, промпты, скрипты, маленькие превью (< 2 МБ).
- **Вне git** (Google Drive / Cloudflare R2 / Backblaze): исходники видео, дубли, LoRA-веса, мастера. В git — только ссылки.
- Контейнер, в котором я работаю, временный. Всё важное пушится в репозиторий в конце каждого шага.

## 6. Автоматизация

Уровни автономности (зависит от того, какие доступы ты дашь):

| Уровень | Что нужно | Что я делаю сам |
|---|---|---|
| 0 (сейчас) | ничего | сценарии, раскадровки, промпты, аниматики, черновой звук, монтажные скрипты, упаковка |
| 1 | API-ключ fal.ai **или** Replicate в секретах окружения | + ключевые кадры (Flux/Qwen/Nano Banana), видео Kling/Seedance/Wan через API, обучение LoRA Фомы |
| 2 | + ElevenLabs API-ключ | + финальные голоса и SFX |
| 3 | + облачное хранилище (R2/S3 ключи) | + полный цикл: генерация → QC → сборка → выгрузка мастера |

На уровне 1–3 сценарий запуска: `python tools/run_shots.py --episode ep001 --class A --takes 3` → генерация, извлечение стоп-кадров, отчёт QC, ты отбираешь дубли.
