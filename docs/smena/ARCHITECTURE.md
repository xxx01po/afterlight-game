# «ПОСЛЕДНЯЯ СМЕНА» — техническая документация

Эпизод 1 «Ночная смена № 01». Психологический survival horror от первого лица для Telegram Mini App и мобильного браузера.
Игра живёт в том же репозитории, что и AFTERLIGHT, но полностью независима: своя точка входа `smena/index.html`, свой код в `src/smena/`.

## 1. Анализ исходного состояния

- В репозитории уже была рабочая игра AFTERLIGHT (Vite 8, React 19, Three.js r187, Zustand 5, Vitest, CI + GitHub Pages).
- Удалять её было не нужно и нельзя («не удаляй работающие части»), поэтому Vite настроен как multi-page: `/` — AFTERLIGHT, `/smena/` — новая игра.
- Общие с AFTERLIGHT только чистые утилиты `src/utils/{math,canvas}.ts`. Всё остальное написано заново под требования ТЗ (физика Rapier, IndexedDB, Telegram, мультитач, ИИ).
- Совместимость версий проверена через npm registry: `three@0.187`, `@dimforge/rapier3d-compat@0.21.0` (вышла 25.09.2026, API `World`, `KinematicCharacterController`, `castRayAndGetNormal`, `setEnabled` подтверждены по `.d.ts`), `react@19`, `zustand@5`, `vite@8`.

## 2. Ключевые архитектурные решения

| Решение | Почему |
|---|---|
| Three.js вручную, **без React Three Fiber** | Порядок систем в кадре (ввод → игрок → физика → ИИ → сюжет → звук → рендер) и стоимость кадра на телефоне проще контролировать без реконсилера. React рисует только интерфейс, HUD обновляется 10 раз в секунду. |
| Rapier (`rapier3d-compat`) грузится **динамическим импортом** | WASM весит 1,6 МБ (gzip). Меню и живой 3D-фон показываются через ~300 КБ; физика догружается, пока игрок читает меню. |
| Двери — **кинематические** тела на петле | Первая версия (динамическое тело с «сервоприводом») засыпала в солвере и не открывалась. Кинематика детерминирована и при этом физически расталкивает предметы. |
| Источники света — **фиксированный пул** | Число `PointLight` не меняется во время игры (только интенсивность и позиция) → шейдеры не перекомпилируются, нет фризов. Остальные лампы — светящиеся колбы + спрайты. |
| Видеонаблюдение — **настоящий рендер** камер в текстуру | Призрак на мониторе находится на отдельном слое, который видит только CCTV-камера. Он действительно «есть только на экране». Рендер идёт 8 раз в секунду и только когда игрок стоит у монитора. |
| Мир = функция от флагов | Сохранение хранит флаги, стадию, двери, инвентарь, позицию; при загрузке мир собирается из флагов, без «переигрывания» событий. |
| Весь контент процедурный | Ни одного файла текстур, моделей или звуков: всё рисуется на canvas и синтезируется Web Audio при запуске. Лёгкая загрузка, нет проблем с лицензиями. |

## 4. Игровые системы

- **Игрок**: Rapier KinematicCharacterController, автоступенька, прилипание к земле, подшаги при низком FPS; ходьба 2,5 м/с, бег 4,7 (выносливость ~7 с), присед 1,35 с проверкой потолка; падение с высоты ранит.
- **Взаимодействие**: луч из центра экрана по короткому списку интерактивных мешей + проверка стен лучом физики. Подсказка видна только при наведении.
- **Физика**: ~40 динамических предметов (вёдра, банки, бутылки, ящики, табуреты, канистра). Дальше радиуса профиля тела выключаются целиком. Сила удара → звук материала и шум для ИИ.
- **Инвентарь**: 6 слотов; ключи и пропуск идут на связку, документы — в журнал. Каждый предмет нужен по сюжету или для выживания.
- **ИИ** (`Creature.ts`): FSM `Idle → Patrol ↔ Investigate → Chase → Attack`, `Chase → Search → Return → Patrol`, плюс `Flee` от ракеты. Зрение: конус 115°, дальность зависит от фонаря, присяда, укрытия, света; «осведомлённость» копится, а не включается мгновенно. Слух: шаги, броски, двери, выстрел (стены вдвое глушат). Путь — A* по графу дорог, лесных петель, дворов и коридоров НИИ; освещённую базу граф обходит. Существо не телепортируется у игрока на виду; при повторной загрузке появляется не ближе 40 м. После трёх смертей становится чуть медленнее.
- **Аномалии**: человек на камере 3 (виден только на мониторе) и исчезает, когда выходишь; собственные шаги за спиной (стихают, если обернуться); фигура вдали, исчезающая при приближении или в луче; силуэт в окне заколоченного дома; рация говорит твоим голосом; предметы в доме переставлены, пока не смотришь; дорога «повторяется» — тот же указатель снова впереди, фонари позади гаснут; шёпот, если долго стоять в темноте. Набор редких событий выбирается сидом прохождения (реиграбельность), но не перебрасывается при загрузке.

## 5. Сюжет эпизода (≈10–20 минут)

1. Будка КПП: фонарь, рация, инструктаж диспетчера.
2. Первый обход: генератор пуст → ключ от склада в корпусе → канистра (нести руками, физика) → запуск (с первого раза не заводится).
3. Камеры: на третьей у ворот стоит человек. У ворот — никого, только длинные следы.
4. Ретранслятор в Сосновке: предохранитель, отвёртка из дома; рация воспроизводит твои же фразы.
5. В лесу дорогу пересекает высокая фигура (существо в «пассивном» режиме: смотрит и уходит).
6. НИИ «Кедр-7»: пропуск с твоим фото, ключ от щитовой, питание; монитор показывает будку, где сидит человек в твоей куртке; журнал «Смена» → камера содержания открывается → погоня.
7. Возвращение к свету базы → архив открыт → рация: «Ты уверен, что сегодня твоя первая смена?» → затемнение → конец эпизода.

## 6. Производительность на телефонах

- Статика склеена по (зона × материал): сотни объектов → десятки draw calls. Оконные рамы, мебель, стены — в одной геометрии.
- Растительность: 12 вариантов деревьев и кустов, ~5000 экземпляров в `InstancedMesh`; каждый кадр в буфер копируются только ячейки 16×16 м, попавшие в пирамиду видимости и дальность прорисовки; ближние — детальная модель, дальние — упрощённая (LOD).
- Ветер — в вершинном шейдере, дождь и пыль — GPU-частицы (одна униформа на кадр).
- Тени только от фонарика и только на «Высоком» (512–1024).
- Пост-обработка — один проход, рендер в уменьшенный буфер (0,75 на «Низком»).
- Профили: Low / Medium / High; «Авто» выбирает по GPU, памяти и ядрам и понижает уровень, если FPS < 26 дольше 6 с.
- Физика 60 Гц с аккумулятором (максимум 3 шага за кадр), дальние тела выключены.

Замеры в headless Chromium с программным рендером (SwiftShader, это намного медленнее любого телефона): 100–380 draw calls, 45–85 тыс. треугольников в кадре. На реальных устройствах FPS не измерялся (см. риски).

## 7. Telegram Mini App

- SDK (`telegram-web-app.js`) подключается **только** внутри Telegram (по параметрам `tgWebAppData` или прокси WebView); в обычном браузере ничего не грузится.
- Вызовы проверяются по версии Bot API: `ready`, `expand`, `disableVerticalSwipes` (7.7), `requestFullscreen` + `lockOrientation` (8.0, только телефоны), `enableClosingConfirmation`, цвета шапки/фона, системная кнопка «Назад» → пауза, вибрация `HapticFeedback` (с фолбэком на `navigator.vibrate`).
- Безопасные зоны Telegram (`safeAreaInset` + `contentSafeAreaInset`) объединены с `env(safe-area-inset-*)` в CSS-переменных.
- Авторизация не нужна, имя пользователя только показывается в меню.
- Подключение: в @BotFather → Bot Settings → Menu Button / Web App URL = `https://<домен>/smena/` (для GitHub Pages: `https://<user>.github.io/afterlight-game/smena/`).

## 8. Сохранения

IndexedDB (`smena` / `kv`), при недоступности — localStorage, затем память. Два слота: `auto` (контрольные точки на каждой смене задачи) и `manual` (пауза → «Сохранить»). Проверка: версия формата, конечность и диапазоны чисел, структура, контрольная сумма FNV-1a. Повреждённое сохранение игнорируется. Настройки — в IndexedDB с синхронной копией в localStorage (чтобы применить их до загрузки базы).

## 9. Тестирование

- `npm test` — 50 модульных тестов (из них 23 для «Смены»: восприятие, FSM, A* и связность карты, инвентарь, сохранения и порча данных, режиссёр, контент, настройки, рельеф). Тест связности нашёл реальную ошибку: узлы навигации связывались сами с собой.
- `node tests/e2e/smena-playthrough.mjs <url>` — прохождение эпизода целиком: прицел + E по двери, ходьба через дверной проём, перенос канистры физикой, все 14 стадий, сохранение → перезагрузка → «Продолжить», смерть → контрольная точка, ракета → бегство существа, финал. Падает при любой ошибке в консоли.
- `node tests/e2e/smena-mobile.mjs <url>` — эмуляция iPhone 13 в ландшафте: одновременный джойстик и свайп, кнопки не запускают поворот камеры и не перекрываются, кнопка действия открывает дверь, пауза и настройки пальцем, нет прокрутки и выделения, подсказка в портрете.

## 10. Технические риски

1. **Производительность на слабых Android** не проверена на реальном железе. Смягчение: профиль Low, автоснижение, отсечение. Первое, что нужно сделать — прогнать на 2–3 реальных телефонах.
2. **Размер Rapier (1,6 МБ gzip)**. На медленной сети «Новая игра» станет доступна позже меню. Вариант на будущее — некомпилируемая сборка `@dimforge/rapier3d` с отдельным `.wasm` (~0,9 МБ) через плагин WASM.
3. **iOS WebView в Telegram**: Web Audio разблокируется по нажатию «Новая игра»; на iOS < 17 переключатель «Без звука» глушит звук.
4. **Синтезированная речь**: реплики рации — формантный «голос» с субтитрами, а не озвучка актёром.
5. Проверка на настоящем Telegram-клиенте вручную не проводилась (интеграция покрыта проверками версий и работает в браузере без SDK).

## 11. Временные решения и оставшиеся задачи

Модели процедурные и стилизованные; это сознательный выбор ради веса и лицензий, но вот что честно стоит улучшить:

- Существо и «двойник» — иерархия примитивов с процедурной анимацией (без скиннинга и лицевой детализации). Заменить на скелетную модель (glTF) с анимациями ходьбы, бега и атаки.
- Мебель, машины, генератор — составлены из примитивов («kit»). Для финального качества — низкополигональные модели с запечёнными текстурами.
- Нет отражений на мокром асфальте, кроме бликов от фонаря и ламп (экранные отражения дороги для мобильного GPU).
- Озвучка диспетчера и героя актёрами.
- Окклюзия звука упрощённая (по зданиям), без графа комнат.
- Нет полноценного оружия ближнего боя: единственное средство защиты — ракетница. Это осознанное решение («обычный человек, не суперсолдат»).
